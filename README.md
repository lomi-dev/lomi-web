# lomi web

A minimal, English-language work-in-progress page for lomi.

## Run locally

```sh
bun install --frozen-lockfile
bun run dev
```

Open http://localhost:4321.

```sh
bun run check
bun run build
bun run preview --port 4322
```

## Page and stack

A single full-height hero contains the lomi wordmark, a work-in-progress message, a preview download dialog, a link to the project on GitHub, and a newsletter signup. The original realistic sky is static. The page has no navigation, product screenshot, FAQ, or footer while the new website is being prepared.

Colors follow the supplied lomi system v1.3 light theme: Soft Chalk (`#F7F8F3`) for the canvas, Ink (`#0B0D0C`) for primary text, and Electric Lime (`#C8FF3D`) for the primary action. Secondary text, hover, pressed, focus, and selection colors also use the original semantic tokens. The existing cloud photograph receives a static grayscale treatment and a uniform Chalk wash; the original asset is unchanged.

- Bun, Astro, React, TypeScript, and Tailwind CSS.
- Static HTML with small client-side scripts for newsletter signup and installer selection; no hydrated islands or animation code.
- React renders the inline SVG icons at build time; no React runtime is downloaded.
- Responsive AVIF/WebP clouds with a PNG fallback, generated by Astro.
- Local Geist and Instrument Serif fonts, preloaded with `font-display: swap`.
- Semantic landmarks, visible keyboard focus, and a skip link.
- No trackers, third-party embeds, or external font requests.

## Preview downloads

The download dialog reads the newest published release from the public GitHub Releases API when it opens, then links directly to the selected installer asset. macOS offers Apple Silicon and Intel DMGs; Windows offers EXE and MSI; Linux offers AppImage, DEB, and RPM. Browser platform detection provides a suggested default, which visitors can change. If a package or the API is unavailable, the dialog links to the releases page.

The operating-system symbols are local SVGs downloaded from Iconify's [Simple Icons Apple](https://icon-sets.iconify.design/simple-icons/apple/), [Windows](https://icon-sets.iconify.design/simple-icons/windows/), and [Linux](https://icon-sets.iconify.design/simple-icons/linux/) icons (CC0 1.0).

## Newsletter setup

Newsletter signup is unavailable by default. The browser sends only an email to
an explicitly configured HTTPS auth backend, without cookies or authorization.
It never calls Plunk directly, embeds a provider key or changes subscription state.
An accepted request asks the visitor to check their inbox and confirm before
receiving marketing updates.

First complete the operator prerequisites in
[auth-app/NEWSLETTER.md](../auth-app/NEWSLETTER.md): revoke/rotate the old published
public Plunk key, qualify a transactional template with its provider-hosted
`{{subscribeUrl}}`, and enable the server only after confirming new and previously
unsubscribed contacts remain unsubscribed until recipient confirmation. This
source change does not perform provider-side qualification or key rotation.

Then set `PUBLIC_NEWSLETTER_ENDPOINT` in the site's build environment to the HTTPS
auth service URL with exactly `/v1/newsletter/confirmation` and rebuild. It must
have no credentials, query or fragment. Remove the obsolete
`PUBLIC_PLUNK_API_KEY` environment setting; never replace it with a secret key.

```sh
PUBLIC_NEWSLETTER_ENDPOINT=https://auth.example.com/v1/newsletter/confirmation SITE_URL=https://your-domain.example bun run build
```

Cloud provenance and the original generation prompt are recorded in [docs/assets.md](docs/assets.md). `public/social-card.png` is a 1200 × 630 browser render of the current hero for link previews.

## Verify

Build and start the production preview first, then:

```sh
PLAYWRIGHT_CHANNEL=chrome bun run verify
```

For Firefox:

```sh
bunx playwright install firefox
VERIFY_BROWSER=firefox bun run verify
```

Override the preview URL with `VERIFY_URL`. The check covers six viewport widths, a short landscape screen, the GitHub link, download selection and fallback, newsletter form states, keyboard access, JavaScript-disabled rendering, and mobile/desktop accessibility with axe. To test a configured form without sending email, build with `PUBLIC_NEWSLETTER_ENDPOINT=https://auth.example.test/v1/newsletter/confirmation`; the verification script mocks the backend and blocks direct Plunk calls. Also build without that variable to verify the unavailable state. Screenshots and audit output go to ignored `artifacts/`.

## Publish

Set the real public origin at build time and upload `dist/` to a static host:

```sh
SITE_URL=https://your-domain.example bun run build
```

`SITE_URL` enables canonical and absolute Open Graph URLs. `_headers` configures caching and basic security headers on hosts that support the file.
